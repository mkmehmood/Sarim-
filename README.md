# Sarim — Gull & Zubair Naswar Dealers

Offline-first PWA (vanilla JS, SQLite/WASM, Firebase sync).

## Setup
```bash
npm install          # installs esbuild
```

## Commands
| Command | What it does |
|---|---|
| `npm run serve` | Serve the **source** at http://localhost:8080 |
| `npm run build` | Bundle + code-split + minify + hash into `dist/` |
| `npm run serve:dist` | Serve the production build |
| `npm test` | Run unit tests |
| `npm run verify` | Check all file references in `index.html` / `sw.js` |
| `npm run check` | verify + test + build + verify dist (used by CI) |

## Layout
```
index.html  sw.js  manifest.json  192.png  512.png  .well-known/   ← must stay at root (PWA scope)
modules/
  main.js                 entry point — statically imports the core files below,
                           dynamically import()s factory.js / rep-sales.js on demand
  constants.js  business.js  admin-data.js  sync.js
  utilities-core.js  utilities-sales.js  utilities-payments.js  customers.js
  factory.js  rep-sales.js  custom-date-picker.js
```

Each file is a real ES module (explicit `import { x } from './y.js'` / `export`).
Every exported name is also mirrored onto `window` for backward compatibility
with inline HTML event handlers (`onclick="..."`) and any dynamic
`window.foo()` lookups — don't remove those `window.x = x;` lines without
checking `index.html` for references first.

A handful of module-level variables (chart handles, a few sync-state flags)
are written to from more than one file. Since plain ES imports are read-only
bindings, those specific names get an exported setter function instead
(`_set_defaultSettings(v)`, etc.) — look for `_set_*` in `utilities-core.js`,
`admin-data.js`, and `customers.js` if you need to add another cross-file
writable global.

## Build pipeline
`build.js` runs `esbuild --bundle --splitting --format=esm` on
`modules/main.js`. `factory.js` and `rep-sales.js` are lazy-loaded via real
dynamic `import()`; esbuild's code-splitting factors out whatever they share
with the core bundle into one chunk, so there's still only a single instance
of each module's state (e.g. the encryption engine's in-memory session key)
— never a duplicate. Output filenames are content-hashed; `build.js` rewrites
`index.html` and `sw.js`'s `ASSETS_TO_CACHE` to match automatically.

## Adding a new module file
1. Add the file under `modules/`.
2. `import`/`export` whatever it needs from / shares with other modules.
3. If it should be lazy-loaded, add a dynamic `import()` for it (see how
   `main.js` handles `factory.js`/`rep-sales.js`); otherwise add a static
   `import './yourfile.js';` in `main.js`.

Then run `npm run check`. `sw.js`'s cache list and `index.html`'s script tag
are generated by `build.js` — you shouldn't need to touch them by hand.
